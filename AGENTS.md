# LifeOS repository instructions

- The assistant may manage the existing LifeOS Development GitHub Project `Status` field and the corresponding issue open/closed state without requesting repeated permission.
- Move an issue to `In Progress` when implementation begins.
- Move an issue to `Verify` only after its full scope is implemented and automated checks pass while required acceptance is still pending.
- Move an issue to `Done` and close it only after the full scope and required acceptance are complete. A commit or deployment alone is not acceptance, and partial work must not advance a broader issue to `Verify` or `Done`.
- Preserve unrelated project fields, priorities, issues, and workflows. Read back every status or issue-state change.
- Git staging, commits, pushes, pulls, branch or history operations, tags, releases, deployments, and version bumps remain user-controlled unless separately authorized.
